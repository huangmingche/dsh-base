# Type checking

Run `node scripts/typecheck/check.mjs`, optionally with `--app <id>` to select an application from `dsh.apps.json`. It uses the selected application's TypeScript 6.0.3 installation from the repository-root lockfile, verifies the upstream pin, then generates declarations and independent Client / Worker configurations. The base default Web app retains `.artifacts/typecheck/`; the consumer default Web app uses `.artifacts/dsh/.artifacts/typecheck/`; other applications use `.artifacts/dsh/applications/<id>/.artifacts/typecheck/`. Every owned Client, Worker and Think TypeScript file under `src`, plus the app runtime entries, is checked with `strict: true`. Excluding an owned source file fails the gate.

Shared official dependencies such as Cordis are checked with their package compiler options and emitted as declarations. The official public Typert `WorkspaceAnalyzer` and `FaceModelEmitter` generate real Remote declarations from the pinned Host source. Other official dependencies use TypeScript `emitDeclarationOnly` / `noCheck` for declaration extraction, then are consumed as dependencies instead of merging all upstream augmentations into one checked source project. `noCheck` applies only to dependency extraction. Owned checking never uses it or filters diagnostics by file path.

This does not claim complete semantic checking of the upstream repository, which owns separate Host / Client project boundaries and tests. No invented interfaces, `any` replacement, submodule writes or upstream workspace installation are used. Generated files can be deleted and rebuilt; a passing report lists the checked owned files. Build and browser acceptance separately verify runtime behavior.

A consumer project runs `DSH_PRODUCT_ROOT=/path/to/product node /path/to/product/.submodules/dsh-base/scripts/typecheck/check.mjs` (`--root` and `--app` are also accepted). Prepare generated files for the same application first. Configuration, official declarations, Remote declarations and the report are written only to that application's type generation directory. TypeScript and browser dependencies come from the selected application's `node_modules`; server SDKs come from its `packages/build/product-server-dependencies/node_modules`. No dependency installation in the base checkout is needed.

Strict checking enumerates Client / Worker / Think plugins and browser support packages from both roots. The compiler host redirects relative generated-module references in base sources and app entries to the selected application's generated directory, even if stale generated files remain in the default app or base; missing selected-application output fails. Root files are redirected too, so plain `tsc -p` cannot replace this entry point. Run `node --test scripts/typecheck/tests/*.test.mjs` for regression fixtures covering strict diagnostics, omitted-source protection and product dependency/generated-file resolution.

Follow the [multi-application contract in AGENTS.md](../../AGENTS.md#multi-application) for selection, batch checks and downstream operations. A selected application ID that conflicts with the build configuration’s application directory must fail instead of silently checking another application.
