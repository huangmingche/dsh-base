# Cloudflare Think Core

This plugin uses Cloudflare Think durable submissions as execution authority, reuses the official DSH system-prompt public entrypoint, and provides admission, history, cancellation and execution projections to Session Host. It does not implement equivalent official DSH agent-loop semantics; `package.json` records reuse decisions and gaps.

Host submits a stable requestId and recovers the existing submission after reconnecting. `ensureHistory` seeds only instances without user history, preserving admitted execution. Cancellation first writes a durable tombstone so late admission is cancelled too. Parent sessions read the Host durable archive gate before model steps and tool calls, and fail closed if the authority is unavailable. Already-issued provider calls have no exactly-once guarantee. Dynamic subagent execution is unavailable; the historical class binding remains readable without advertising a nonfunctional delegation tool.

Admission updates instruction snapshots independently on the current branch and appends new snapshots at its current leaf. This avoids Think's batched upsert making an old context ID the parent of new messages and branching away from the conversation. A stranded legacy context row is safely spliced out through the public Session deletion API, then appended to the active branch. Empty or deleted files clear their instructions. Host read or SQLite write failures block admission and partial writes can be retried. A requestId marker is stored only after verification; replay and recovery after that marker do not rewrite instructions. Time snapshots use IDs unique across restarts, with the newest 20 retained at the next admission.

Permission state comes from the separately forked official permission service. Every action rereads its Session policy. `approval: never` denies consent-requiring actions and never automatically approves `remember_fact`; Host policy and alarm recovery deny pending requests. Logical R2 model writes have a dedicated permission boundary, while explicit user file editing uses a separate service. This does not provide a POSIX process sandbox, arbitrary shell execution, or one-off filesystem escalation grants.

Each `beforeStep` reads the current context and durable transition notices produced by official ApprovalService/SystemPrompt. Actual Sessions append APIs retain notices as non-human `source:user-approval` context without waking inference or creating an admitted input/statistical turn. Durable message IDs deduplicate restart delivery; private Symbol provenance identifies already-inserted notices across SDK steps without text matching or provider parameters. Admission context refresh preserves them. Invalid or unavailable authoritative policy context blocks the step. Canonical UI history for commands/notices and full native Agent inbox scheduling/cancellation remain tracked differences.

Root `pnpm check:session-host` runs real SQLite Host and Think RPC port fault-window tests covering lost responses, restart, cancellation, archive gates and usage replay. `tests/durable-context.test.ts` also uses the installed `agents/sessions` implementation with real SQLite to verify user/assistant history preservation, instruction changes/removal, stranded context repair and Host/write/admission fault recovery. It does not call production providers.

SQLite transactions retain the mapping between logical inputs, SDK request identities, decisions and continuation intents. `beforeTurn` identifies the actually admitted user from active history and carries that requestId on live frames. `onChatResponse` settles only the matching SDK request: stale hooks, cancellation and lost RPC responses cannot fabricate completion or blindly repeat admission. Parallel approvals wait for all decisions; denial is a tool result, not cancellation of the user's request. Prepared intents can retry, while started executions remain owned by SDK recovery. Legacy message IDs require an explicit Host-proven alias. Model and effort are frozen at admission and reused by approval continuations. Trusted request evidence updates Host lastUsed. Assistant attribution distinguishes the requested model from actual provider response.modelId, preserving unknown when no response evidence exists and retaining provider usage. Later selection changes cannot rewrite history.

`tests/input-execution.test.ts` uses real SQLite, installed Sessions, the SDK's actual tool-approval transition and this package's hooks while isolating model transport. It covers decision replay/conflicts, parallel approval, denial, failures, cancellation, stale hooks, restart, lost replies and legacy aliases. Tool decisions still require the SDK's private `_applyToolApproval` and fail explicitly if it is absent; inference uses public `continueLastTurn`. This compatibility boundary is recorded in reuse metadata.

The actual `onStepEnd` hook persists cumulative step statistics, and `onChatResponse` finalizes a repeatable snapshot keyed by SDK requestId. Replayed hooks or the legacy destructive `takeTurnStats` read cannot erase it. The Host adds continuation timing, tokens and usage once per SDK snapshot. Unrecoverable historical timing is not invented; footer turns/steps come from actual user messages and durable `step-start` partitions, including several model steps inside one assistant message.

Actual `onChunk`, `beforeStep`, `onStepEnd` and tool hooks record argument streams, stable Step identities and real clocks. Late approval tool clocks are durable and remain attached to the original Step after reload. Host expands this evidence into stable single-Step rows; model seeds omit internal projection metadata. Missing provider system/tools token breakdown is not replaced with a character-count estimate.

Before inference or live delivery, `beforeStep` persists Step entry through a trusted internal RPC. Host verifies the frozen input and actual SDK request identity. A failed write stops that execution; retries retain the Agent's durable original clock and identity. If the provider fails before its first token and produces no assistant message, Host history still reconstructs the entered Step and closes it at the authoritative failure or cancellation time, without inventing an assistant reply.

Legacy pending inputs without durable model/effort configuration cannot safely recover their original execution and return `input_configuration_unavailable`. Host preserves the approval and cancel/resubmit path, stops blind automatic retries, and never substitutes the current picker for historical configuration.
