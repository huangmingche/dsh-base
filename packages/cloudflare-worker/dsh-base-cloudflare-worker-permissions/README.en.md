# Workers session permissions

This package is a complete, marked fork of pinned `@deepseek-ai/dsh-permission-presets`. The official preset derivation, defaults, command, projection and three policy event algorithms remain unchanged. The required native shell executor is replaced with an enforcing logical R2 file boundary. This is not a native shell, PTY or operating-system sandbox.

The source is `.submodules/deepseek-harness/packages/interaction/permission-presets`, commit `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`, MIT. `src/presets.ts` corresponds to upstream `src/index.ts`; `src/types.ts`, `src/client.ts`, all eight locale JSON files and the MIT license are retained directly. Metadata records `forkOf` and the Worker composition entry `cloudflare:worker:permissions`.

Adaptations replace `shell` with `permissionExecutor`, retain the Agent-created listener without fabricating an Agent service, expose the same initialization algorithm to Host admission, and add synchronous Host and R2 enforcement interfaces. Official Session, SessionProjectionRegistry and ApprovalService mount unchanged through stable exports. Read-only is added through the official preset configuration table. Auto review is not configured or selectable.

After activation, `createPermissionRuntime()` provides synchronous `initializeSession`, `selectPreset`, `snapshot` and `catalog` methods. A genuinely new session passes `null` and uses the current user default. An existing session with no permission journal passes `[]`, retaining the official restored-session behavior instead of adopting a later default. Journals preserve complete official `seq/time/type/data` envelopes. Changes write `permission/preset`, `sandbox/mode` and `approval/policy`; repeat selections do not write. A restore-generated `session/end-seed` is retained internally only when a real change is committed.

The Session Host `PermissionStore` requires a real `transactionSync`. It atomically merges the permission journal, effective snapshot and Host notification events while preserving existing projections such as model selection. It never falls back to non-atomic writes. The public `permissions` projection remains the official `{ currentValue }`; execution uses the separate `{ currentValue, sandbox, approval }` snapshot. User defaults affect only new sessions, and forks inherit the source policy.

The default-permission form options and write validation share the actual mounted service's configured preset table. `settings/mutate`, `update` and `replace` validate the final value after all operations. Unknown names, unavailable Auto, derived Custom and invalid types are rejected before SQL writes, revision changes or notifications. Unsetting the field or replacing its section with an empty object still restores the composition default. Real SQLite and Remote regressions cover all paths, transaction rollback and SQL failure.

Before every model file effect, tools must read the latest persisted policy and call `assertFilePermission`. Read-only rejects writes; workspace-write confines writes to the session workspace; full access permits other logical workspaces belonging to the same authenticated owner and never crosses accounts. Paths are not implicitly decoded and reject traversal, backslashes, NUL and alias segments. Explicit user file editing and model tools have separate authorization. Filesystem policy does not restrict network fetches and provides no POSIX, process or shell isolation.

`approval: never` rejects operations that require consent; it does not approve them automatically. Memory writes still require consent. Already pending approvals must be rejected and continued through the Host's durable approval workflow. Tool wiring and restart recovery belong to the Session Host / Think packages; this library alone does not claim to implement the entire execution chain.

Run `pnpm check:permissions`. Tests compare the actual unchanged official service with this fork for defaults, replay, shared-bundle aliases, drift and no-op behavior; verify the R2 boundary; and use real SQLite for rollback, independent defaults, forks, restarts and concurrent serialized changes. Host `remote-permissions.test.ts` covers actual owner routing, current defaults, error propagation and strict argument validation. Tests make no cloud or model calls.

`commands/list` returns the official permission command descriptor. `commands/execute` uses the official parser and the original handler within this complete fork. The Host commits `command/run`, policy changes, `command/done` and a real execution receipt in one transaction, with idempotency keyed by the authenticated RPC ID. Reusing an ID with different input conflicts; repeated delivery never repeats the operation; rejected attachments trigger no upload. Failed receipts surface as Remote errors carrying the real `commandId`, never a fabricated client success.

Approval-policy notices come from unchanged official `ApprovalService.setPolicy`; the current policy statement comes from unchanged `SystemPrompt` / ApprovalService context. No prompt strings are copied or rewritten. `ApprovalPolicyAgentPort` borrows only a real Session and a non-waking `inject` receiver; it is not a native Agent. Both narrow calls require review when the upstream pin changes. Host commits the notice outbox and policy facts together; initialization, no-op selection and failed transactions enqueue nothing. Think reads notices at the actual next model step and persists their original ID/source. Restart, command retries and later SDK steps do not duplicate delivery or add user requests/turns.

Command events and model-context notices are not yet merged into the shared official chat trajectory. This does not implement the full native Agent inbox scheduling/cancellation protocol. Execution checks still read the latest durable policy. Native `tool-fs` per-operation `sandbox_permissions` / `justification` escalation grants are not exposed; R2 uses the standing session policy. These are implementation differences, not physical Workers limits, and do not establish complete native command-trajectory or sandbox equivalence. `approval-context.test.ts` exercises switching, rollback, restart and non-waking delivery with real DO/SQLite, installed Sessions and a multi-step AI SDK fixture, without calling an online model.
