# Confirmed newsletter subscriptions

Enable `NEWSLETTER_ENABLED=true`, configure `RESEND_API_KEY`, the existing email plugin, canonical `AUTH_BASE_URL`, `TURNSTILE_SITE_KEY` and secret `TURNSTILE_SECRET_KEY`. Apply this package's schema and the HTTP public-form/email schemas to `AUTH_DB` through the repository's guarded plugin-schema provisioning. The newsletter schema includes additive `revision` and `operation_at` columns for older drafts. No cron, broadcast sender or extra database is introduced.

- Public `GET /api/saas/newsletter/status` reports configuration readiness and a public Turnstile site key.
- Public same-origin `POST /subscribe` accepts `{email,consent:true,turnstileToken,locale?}`. Turnstile must match the canonical hostname and `newsletter` action. Durable fixed-window budgets allow 5 requests/IP/10 minutes, 1000/action/day and one confirmation email/address/10 minutes. A random 256-bit confirmation token is emailed; only its hash is stored, and it expires after 24 hours. Accepted requests return 202 without revealing provider membership.
- Same-origin `POST /confirm` with `{token}` claims the token before changing Resend contact state. Duplicate confirmed clicks read current provider state. No subscription is created merely by submitting an address.
- Authenticated `GET /api/saas/newsletter` reads only the verified session email's real Resend state. Same-origin `DELETE` unsubscribes that verified owner. Confirmation and account management remain independent of email-sender/Turnstile readiness, but ordinary operations require the feature enabled.

Ambiguous writes retain `confirming` or `unsubscribing` instead of racing a later opposite operation. Administrators can recover them using `GET /api/saas/newsletter/reconcile`, which returns `{items:[{email,state,revision,operationAt,reconcilable}]}` without token hashes. Same-origin `POST` accepts `{email,expectedRevision,reviewedProvider:true}`. First verify in provider records that the original request has settled; recovery requires at least 60 seconds since its claim, reads real Resend state and uses a revision compare-and-swap to restore `confirmed` or `revoked`. It never sends a subscribe/unsubscribe write. Conflicts or failed provider reads keep the lock. This administrator recovery also works when collecting new subscriptions is disabled.

Resend requests use a fixed HTTPS origin, bounded response parsing, an eight-second timeout and manual redirect rejection. A GET 404 means unsubscribed; failed GETs never appear as false. No automatic provider retry or migration is supplied. Local consent is not a broadcast scheduler.

`tests/reconcile-runtime.test.mjs` covers real D1 concurrent recovery, administrator checks, provider outages and verified opt-out without email availability. HTTP `tests/outbound-runtime.test.mjs` exercises native Workers fetch against mocked Resend/Turnstile. No real contacts or emails were changed. Protocol reference: [Resend retrieve contact](https://resend.com/docs/api-reference/contacts/get-contact) and [update contact](https://resend.com/docs/api-reference/contacts/update-contact).
