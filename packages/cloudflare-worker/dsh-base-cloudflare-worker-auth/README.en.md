# Worker account authentication

This plugin uses Better Auth 1.7.18 and the existing `AUTH_DB` D1 database for product accounts, passwords and sessions. The official account stack provides DeepSeek OAuth and platform billing rather than local product authentication. The client seam continues to mount the official Account UI, with unavailable billing capabilities visibly disabled.

HTTP authentication requests use Better Auth's native `rateLimit.storage: "database"` with the `rateLimit` table already created by `apps/web/migrations/0002_username_password.sql`. Its conditional increments atomically consume a shared per-IP/per-path budget across Worker isolates and process restarts. There is no memory fallback or custom counter. This change adds no migration and changes no database identity, user ID or signing secret. Missing schema or D1 failures reject authentication instead of bypassing admission or issuing cookies. See [Better Auth rate limiting](https://better-auth.com/docs/concepts/rate-limit) for the database backend and the distinction between HTTP and internal API calls.

Only the `cf-connecting-ip` header overwritten by the Cloudflare edge is trusted; caller-supplied `X-Forwarded-For` is ignored. Better Auth normalizes IPv4 / IPv6 and shares IPv6 budgets by `/64` subnet. Username login, email login and enabled signup each allow 20 requests per minute; ordinary paths allow 600, and `get-session` allows 1200. Exhaustion returns 429 with `X-Retry-After`. This is persisted authentication-endpoint throttling, not account-wide protection against attacks from many source IPs, product API quotas or model spending limits. Internal `auth.api.getSession` calls bypass the HTTP limiter.

Registration is closed by default. Signup requires explicit enablement or the administrator provisioning token; the public policy endpoint exposes only the enabled boolean. Cached instances are recreated when the D1 binding, authentication origin or secret changes, without modifying those settings.

Run `node packages/cloudflare-worker/dsh-base-cloudflare-worker-auth/tests/rate-limit.test.mjs`. Two actual local workerd isolates share persistent D1 to test exact concurrent admission, restart persistence, expiry races and pruning, IPv6 normalization, real signup / login / cookie sessions, and database failure denial. Tests use random secrets and a temporary persistence directory, with no deployed database or model access. `tests/policy.test.ts` additionally verifies closed registration, controlled provisioning, retired-account rejection and cached configuration updates.
