# Client Core

This package is the browser boot and static module transport compatibility layer, not a composed feature plugin. The app entry passes its generated composition to `startClient`, which directly reuses the pinned official `BootPage`, `bootClient`, Loader, `mountClient`, and static module seeds. Reviewed official `./src/*` entrypoints and the source commit are recorded in `package.json` under `dshBase.reuse`.

The source lives in `packages/boot/dsh-base-client-core`; its public package name remains `@dsh-base/client-core`. `dshBase.boot.kind: browser-support` explicitly classifies it as a browser support library: it declares no composition row and owns no product capability. Client feature plugins remain in `packages/client/`. Boundary and strict type checks continue to cover this package in the client plane; Worker, Think, and platform-neutral shared packages cannot import it.

Client plugins may declare exact public document paths through `dshBase.client.documentRoutes`. A matching route starts only those providers through the official Loader, without reading private control state, starting other application plugins, or mounting the private shell. A disabled public provider retains route ownership and fails explicitly instead of falling back to the private composition. The login plugin currently owns `/login`, its surface, and its official theme resources. All other routes retain the complete generated composition, official inventory, and real fiber states.

`node packages/boot/dsh-base-client-core/tests/document-routes.test.ts` checks exact matching, disabled-provider refusal, and preservation of the private inventory. After building, `pnpm acceptance:local` verifies that English and Chinese login pages request only `/api/auth-policy`, create no WebSockets, and start only the login fiber; it then checks the complete signed-in official composition. This boot isolation does not replace Worker authentication and access control.

Full-shell startup and Host seams share one checked account snapshot. A confirmed anonymous session skips private plugin-control reads and uses the static composition; authenticated control failures remain errors. Account reads refresh initially, during explicit sign-in, or on focus, without idle polling. Waiting streams cancel immediately, and opened private streams are revoked on logout, account change, or authentication failure. Worker authentication remains authoritative. `node packages/boot/dsh-base-client-core/tests/control.test.ts` verifies zero anonymous private-control requests and truthful failures; `node packages/client/dsh-base-client-session-adapter/tests/account-session.test.ts` covers the shared snapshot and cancellation boundaries.
