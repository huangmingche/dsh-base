# Global site settings

Contributes the complete `dsh-base:global` editor through the official `plugins.bundle.config` slot and individual SEO, sitemap, robots.txt, manifest, llms.txt and Google Analytics editors through `plugins.row.config`. The official detail page retains its title, artwork, back control and component list. This plugin directly uses the stable `SettingsForm`, `SettingsValueField`, `Button` and `Switch` exports. The pinned DSH has no site SEO, discovery-file, analytics or site-administrator editor; general/shell Host namespaces cannot represent a site document. A minimal field editor and CAS draft controller supply that contract without copying an official page.

Edits site identity, public links, page copy for all eight languages, every icon path, share-image dimensions/type, manifest values, extra robots rules and overrides for registered public pages. Keywords and rules use one item per line; keywords may be empty. Images accept existing asset paths or HTTP(S) URLs, with no upload control. Client and Worker validation share `@dsh-base/site-config/settings`.

Individual entries use the official `<bundle>#<rowId>` key: `dsh-base:global#cloudflare:worker:{seo,sitemap,robots,manifest,llms}`. Google Analytics uses both `dsh-base:global#client:google-analytics` and `dsh-base:global#cloudflare:worker:google-analytics`. SEO edits page copy, site identity and sharing information; sitemap edits only priority, frequency and dates within `seo.pages`. Resetting a page's fields affects only the current capability and preserves the other capability's values. Public site links remain in the complete bundle editor. Manifest shows only its values and the installation icons it uses; the shared SVG path still comes from the same document.

llms.txt can be enabled or disabled and has introduction and guidance fields; it defaults to enabled. Google Analytics defaults to off. A measurement ID can be saved before explicitly enabling collection. Enabling requires an API secret in the deployment; collection covers public page views, without full user attribution. The API secret never enters the form or public configuration. Switches only stage edits; the official Save action applies them.

Authenticated users read `GET /api/site-settings`; only server-authorized site administrators can edit. `PUT { expectedRevision, values }` saves the complete document in one transaction. The UI cannot submit writes for ordinary accounts, and the server independently checks authorization. The form distinguishes deployment settings from saved site settings.

All scopes share one document and revision, and saving a scope preserves the other capabilities' values. Editing only stages a draft. Failures and version conflicts keep edits and never report success. “Reload and discard changes” explicitly replaces the draft only after a successful read. Saving blocks duplicate submissions and editing. A successful save refreshes public `siteConfig`, updating the sidebar name. Leaving the form or switching scopes follows the official `SettingsForm` behavior of discarding unsaved edits.

Multiline fields reuse official `fields.module.css`. Language, page-path and change-frequency native selectors directly use the official model settings `ModelsSection.module.css` `input` / `selectInput` classes: 32px height, maximum 240px width, a 12px inset chevron, and official focus/disabled states. Stable primitives do not export a select field; exact source exports and the pinned review commit are recorded in `dshBase.reuse` for upgrade review. Native keyboard behavior and associated labels remain intact. Language selection only changes the viewed content and remains available to readers; page and frequency edits still require site administrator permission. No dashboard, plugin-page navigation or custom tabs are added.

Check: `node --test packages/client/dsh-base-client-global-settings/tests/*.test.mjs`. Covers actual slot keys, scope field isolation, eight-language labels, rendered comparison with the official Switch, preservation of other capabilities' values, read-only authority, complete CAS saves, conflicts, validation/network failures, concurrency and lifetime. Real Worker/browser acceptance separately checks official form mounting and public site outputs.

## Conversion summaries and dynamic pages

The Analytics editor reuses official fields/select styling for off, first-party aggregate and Google conversion modes, plus campaign labels. Only administrators mount the last-30-UTC-date summary at /api/site-analytics/conversions, which independently enforces server authorization. Page override choices use the snapshot publicPagePaths inventory; configuration cannot publish routes.

Saved SEO overrides for withdrawn pages remain readable without republishing the page. Administrators can explicitly remove them in the global editor; writes still accept only currently registered public paths. Withdrawing a page does not prevent the entire settings editor from loading.
