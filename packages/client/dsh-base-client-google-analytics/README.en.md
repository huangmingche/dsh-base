# Google Analytics and conversion consent

An independent DSH client plugin. Public page views and conversions are configured separately and are off by default. Production first reads published paths and actual languages from same-origin `/api/public-pages`; an unavailable inventory never falls back to static paths. Public noindex pages can be counted. Drafts, unavailable language variants, login, workspace and session addresses are excluded. The Worker independently validates each page; the browser inventory cannot grant access.

Once public page counting is enabled and server readiness confirmed, the client submits only `{ path }` to `/api/site-analytics/google`. Official native navigation, back navigation and locale changes remain intact. State or fragment changes on the same path do not duplicate counts. Queries, document titles, referrers, accounts, Session/Workspace IDs and credentials never enter the payload. Requests omit cookies and Referer. Private navigation, disablement and disposal cancel pending events; failures never retry.

Administrators set `analytics.conversions.mode` to `off`, `aggregate` or `google` in the unified site document. Aggregate mode keeps only first-party daily counts. Google mode does not imply user consent: an unchanged official Switch in Settings → General requires an explicit grant before this tab's registration, checkout and verified payment actions can be sent by trusted server hooks. The switch stays visible, disabled and localized when unavailable. Consent lives only in plugin memory and resets on revocation, refresh or disposal. No cookie, localStorage, sessionStorage or persistent visitor identity is created. The first completed AI turn is counted locally without inheriting browser consent.

`conversionConsentSnapshot()` and `conversionConsentHeaders()` are the account/payment adapter contract. After consent, one `utm_campaign` value is retained only when it matches the administrator's `analytics.conversions.campaigns` allowlist. Full URLs, other query parameters and referrers are never stored. The payment plugin snapshots explicit consent at checkout for the trusted payment webhook; browsers cannot submit a purchase. Raw account and order IDs never reach Google.

The pinned official product-analytics plugin targets Desktop RPC with account/Session context and has no website GA4 or conversion-consent implementation to mount or fork. This plugin reuses the official General slot, Switch and field styles, changes no official navigation, and injects no gtag or third-party tracking script. Reuse decisions and exported source entries are recorded in `package.json`. Each Measurement Protocol event gets a fresh random identifier; this does not claim complete user attribution or verified Google reports. See [Measurement Protocol](https://developers.google.com/analytics/devguides/collection/protocol/ga4).

Validation: `node --test packages/client/dsh-base-client-google-analytics/tests/*.test.mjs`. Tests cover configuration, published inventory, navigation, deduplication, consent and disposal. Actual Chromium compares official Switch pixels and keyboard behavior across English/Chinese, light/dark and desktop/narrow layouts, and checks that no storage identifiers or third-party requests appear. All event traffic is intercepted locally; no real GA property receives events.

The public-page subcomposition requires only siteConfig; official slots/locale are optional UI injections, so public counting does not depend on the workbench. siteAnalyticsConsent exposes the same in-memory controller. PublicConsent from /consent-ui reuses the same field and official Switch for an explicitly configured public consent surface; it never grants consent automatically.
