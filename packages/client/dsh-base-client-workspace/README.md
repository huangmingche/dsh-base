# 工作区导航可用性分叉

完整复用固定版本的官方 `@deepseek-ai/dsh-client-ui-workspace` 浏览器源码与语言资源，来源为 `.submodules/deepseek-harness/packages/client/ui-workspace`，提交 `9c2670d3bce5275e0d1610272958121af87787bb`。MIT 许可见 [LICENSE](./LICENSE)。官方原插件保留在组合库存中并禁用，本插件通过 `replaces` 接替。应用入口不承载本能力。

会话首页选择器和 `workspace.picker` 工厂共用账号检查。登出会卸载选择流程，异步创建完成后再次核验账号状态。

官方插件假定 Host 工作区导航已经获得账号访问能力，其内部注册的浏览区、目录流、快捷键和 `uiWorkspace` 服务没有账号可用性配置。仅替换导出组件不能阻止快捷键或启动恢复访问私有数据，因此采用完整标记分叉，只适配 Host 的已验证账号状态：

- 匿名用户可以点击工作区搜索、视图选项和添加入口，在执行账号操作前打开登录弹窗。`checking` 和 `error` 状态仍以官方 Tooltip 显示原因并禁用操作。布局与启用态样式保持官方实现。
- 按用户在 2026-11-17 的明确要求，匿名工作区列表留空，不再显示额外的图标、登录提示或链接；标题、操作入口与布局占位保留。检查中和错误状态沿用官方 `EmptySessions` 的结构和样式。会话 hero 打开选择器时仍转为登录弹窗，不挂载私有目录流程。
- 服务动作、目录调用、创建/重命名/排序回调和启动恢复统一检查账号。新会话、搜索和添加工作区快捷键在匿名状态请求登录，私有会话操作保持拒绝；快捷键从解析到执行再次检查。账号状态失效时撤销主会话引用、待处理导航和菜单，隐藏旧账号行，丢弃已失效的异步目录结果。
- `navigationAccess` 只是额外前置条件。认证后仍使用真实官方 `RemoteAccess` 的资源授权和 Host 行为，不创建本地权限、不放宽服务端权限。

已登录时保留官方浏览树、列表、水印、拖动、菜单、排序、快捷键、目录流程、语言字典和服务语义。公共 Cordis、Session reference 和 slot 类型沿用官方 `/client` 身份；内部 toast 声明保留原版，因为官方稳定声明输出不携带该私有合并。`entry.ts` 仅提供本地 Loader 的配置契约。升级上游 pin 时复核这些适配点。

回归执行：

```sh
node --experimental-strip-types packages/client/dsh-base-client-workspace/tests/navigation-access.test.mjs
```

测试使用真实固定版 Cordis/store 和本分叉服务，验证拒绝态不调用 Host、认证与资源授权相互独立、登出撤销引用、失效异步响应、旧账号快照隔离以及快捷键二次校验。官方对照和浏览器验收由工作区导航专项统一执行。
