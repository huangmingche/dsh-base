# Capability packs

`packs/<id>/pack.json` is the **single source** for what is composed into the
app. The client roster (`virtual:dsh-composition`), the Worker roster and the
Think roster are all derived from these manifests; package metadata only says
how one package is loaded, never whether it is composed.

- `planes.client` accepts a package name (metadata comes from that package's
  `dshBase.client`) or a full row object for rows without a package of their own,
  including the disabled official inventory.
- `planes.worker` / `planes.think` list package names; `dshBase.worker` and
  `dshBase.agent` supply module/id/order/export.
- Declare only planes that have members. An explicitly empty plane is an error.
- `requires` lists pack ids that must be composed too; unknown targets, cycles
  and self-references fail the loader.
- `toggleable: "L1"` means the pack may be switched off; a member listed in
  `CLIENT_PLUGIN_POLICY.required` (see
  `packages/boot/dsh-base-plugin-management/src/index.ts`) is rejected in an L1
  pack. `none` is deployment-owned.
- Rows sort by `order`, then composition id. Pack directory or declaration
  order never changes the generated bytes.
- `reuse` records the official-reuse decision (`mode`, `official`, optional
  `reason`); forks also record `dshBase.forkOf` on the package itself.

Add a pack: create `packs/<id>/pack.json` (schema:
`scripts/composition/pack.schema.json`), list its members, then run
`pnpm check:packs` and `pnpm check`. Generated rosters are ignored build outputs
written by `pnpm check` / `pnpm --dir apps/web build`; never edit them by hand.

Failure is closed: a missing `packs/`, duplicate pack id or member, missing
package metadata, broken `requires`, empty plane, no-member pack, or an L1 pack
that contains a required module exits non-zero instead of producing a partial
roster.
