## Official plugin changes in 0.2.2-rc.5

Both tag trees contain the same 374 package names under `packages/*/*`, with identical `dsh` declarations and `exports` maps. Seven existing packages changed beyond their version number. One declares a client entry. [Package comparison](evidence/dsh-v0.2.2-rc.5-packages.tsv)

| Official packages (prefix `@deepseek-ai/dsh-` omitted) | Change in rc.5 |
| --- | --- |
| `base`, `web` | The default bundle selects search providers automatically and keeps HTTP as the fetch default. Searches and readiness checks both use the session’s model route. The `deepseek-official` and `deepseek-account` routes prefer DeepSeek server-side search. All other routes, including requests without a route, prefer DeepSeek Search API. |
| `tool-web`, `tool-cordis` | The search tool passes the model route with every query, including batched queries. The Cordis service catalog updates its descriptions of search and provider discovery. |
| `web-search-deepseek`, `web-deepseek-api` | Server-side search prefers a nonempty snippet supplied with each source and falls back to a matching citation excerpt. The Search/Fetch API package updates its documentation only. |
| `client-ui-settings-web-search` | The official Web Search & Fetch card updates all eight locales. Selecting Automatic displays the model-based rule and a guide link. “DeepSeek (legacy)” becomes “DeepSeek server-side search.” |

An explicit provider selection takes precedence. A missing or unavailable configured provider returns an error. In automatic mode, if the preferred provider is unavailable, the Host uses the sole usable provider. Zero usable providers yield an unavailable error. Multiple usable providers require an explicit choice. DeepSeek server-side search has no per-search charge, while the Messages request can still consume model tokens.

The Web profile mounts the official settings plugin. The Workers Host reports the catalog as unavailable through `web/listProviders`, and the Plugins page uses the official form for its disabled state. Cloudflare Think’s independent `fetch_url` tool can fetch authorized URLs. The upstream search routing and pricing rules apply to Hosts with the corresponding search providers installed.

All 16 recorded forks have identical upstream files across the two tags apart from manifest versions. Across 29 packages, 216 declared source entries refer to 156 distinct paths. Two target files changed, both in `dsh-client-ui-settings-web-search`. Plugin management and Web parity fixtures import `WebSearchCard.tsx`, and Web fixtures also import `locales.ts`, accounting for three declarations. To reproduce the package comparison, run this command at the repository root.

```sh
node scripts/dsh-source/compare-packages.mjs dsh-v0.2.2-rc.4 dsh-v0.2.2-rc.5
```

The base lists the workbench homepage in eight languages in its public page registry. Waffo Pancake shows configured plans and provides checkout in its workbench panel. Products can supply articles, guides or a standalone pricing page through their own dsh plugins and register the corresponding paths. [SaaS plugins and server-side entitlements](saas-plugins.en.md) · [SEO and conversion measurement](seo-plugins.en.md)

The Session header menu was missing because `dsh-session-log-export` existed only as disabled inventory. The pinned official client now mounts unchanged, with a Worker seam connecting its server exporter. Markdown and ZIP exports use events saved by the current Host and admitted attachments; they do not establish full native Agent request logs or unrecorded history. RC4 registers Open in app in both the Session header menu and the Session row menu. Workers has no local application launcher. Session ZIPs use the upstream `attachments-missing.txt` for admitted attachments confirmed missing in R2. Cross-session access and storage read failures produce distinct authorization or read errors. Feedback retains the official dialog and its existing disabled submission state. The Files sidebar shows the disabled official button with a localized explanation when a workspace directory is selected and the loaded catalog has no eligible opener. A Host with an eligible app keeps the original launch action.

These were not Worker limitations: real model/effort persistence and admission-time execution snapshots; canonical official model IDs with requested and returned provenance kept separate; per-session permissions using the marked official preset fork and actual R2 enforcement; committed owner notifications and cross-tab refresh; real SDK tool/step evidence; evidence-backed `lastUsed`; exact event-prefix forks using unchanged `buildForkSeed`; persistent D1 authentication limits; official Cron and DST handling; restored official preset roster and declaration reading; rejection of invalid permission defaults before any settings write/revision/notification; removal of invented context-token breakdowns. Final acceptance is recorded separately.

Steps that fail before the first token retain their actual durable start and failure trajectory on cold reload. Fresh Agent history sync retains existing Host timing and model provenance without replacing newer tool results.

Approval continuation now deduplicates repeated SDK Steps within one user Turn and merges actual tool results without letting an earlier snapshot overwrite a terminal state. Affected completed historical records are repaired transactionally from already-persisted Agent SDK messages. Recovery never reruns the model or tool and never invents a missing result.

Approval presentation follows committed notifications and real Session subscription lifetimes instead of a timer. Reads are serialized per Session, identical call IDs are isolated across Sessions, and cancellation of the official PendingApproval never submits rejection. Only an actual user choice is sent; a lost acknowledgment can retry only that same idempotent choice. HTTP, business and presentation failures remain errors.

The unchanged ApprovalService generates policy-change notices and SystemPrompt generates the current policy context. Policy and notices commit in one Host transaction; the next SDK step consumes stable message IDs without waking the Agent or adding user Turns. Initialization, no-op selections and failed transactions produce no notice; restarts do not duplicate delivery. This narrow Host port does not supply the native Agent scheduler.

The unchanged Typert registry and RemoteAccess client replace the fixed browser owner snapshot. An isolated unchanged Gateway owns generated contracts and the sole connection lifecycle. Access stays denied until the authenticated Host confirms the owner baseline, reconnects through official supervision, and withdraws namespaces/subscriptions on unmount. The former custom connection bootstrap remains disabled inventory.

Forks exclude later tool results from both UI history and model context, preserve the exact seed across restarts and continuation, and retain workspace membership. Their default boundary is the latest closed-turn prefix. Aggregate usage beyond an inherited cursor is not assigned to the branch. `approval: never` rejects operations that require approval; it does not grant consent. File sandbox policy does not claim to govern network requests.

## Actual boundaries of the current Worker-only deployment

| Capability | Concrete boundary |
| --- | --- |
| Native terminal, PTY, subprocesses and native executable tools | Worker isolates do not supply native process/PTY execution. A container or remote executor would add an execution plane. Official terminal controls remain visible and unavailable. |
| User-computer folders, persistent POSIX filesystem, native settings editor | R2 logical workspaces are not the operator's disk. The Worker VFS does not supply persistent native filesystem semantics. Browser grants or a local companion are required for native access. Logical browsing/files/preview remain available. |

Sources: [Workers Node compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/) and [filesystem](https://developers.cloudflare.com/workers/runtime-apis/nodejs/fs/).

The pinned Node Gateway uses `ws.ping()` in `packages/api/gateway/src/stream-server.ts` to check its connections. The Workers carrier uses the message and close events of `WebSocketPair` and the official client restores its subscriptions after a disconnect. Cloudflare can retire a connection, but failing to recover from that loss is not a required platform deviation. Synchronized browser and Tail evidence on the intermediate build captured `loadShed` alongside one `session/follow` close code 1006; that does not establish a fixed timeout or a specific CPU/memory cause. Cloudflare's [WebSocket lifecycle documentation](https://developers.cloudflare.com/workers/runtime-apis/websockets/#connection-lifetime) also requires reconnection and state recovery. The seam must use the official RemoteStream recovery contract for physical carrier loss while preserving business and protocol failures. Final repair/deployment evidence is recorded separately.
