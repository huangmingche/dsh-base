# Browser comparison with official components

Run from the repository root:

```sh
pnpm acceptance:parity
```

The full command runs the remaining parity runners sequentially. `node apps/web/tests/parity/run.mjs` runs only the main reference cases; each runner retains its own report and scope, and the current complete command determines acceptance status. Not all cases are pixel comparisons.

The script uses the application's installed Vite and Puppeteer, builds an isolated fixture, starts a temporary local preview, runs Chromium, and closes both. It never accesses a deployed account, creates real tasks, or calls a model. All runners use the shared macOS/Linux/Windows browser finder. Set `CHROME_PATH` for the browser and `DSH_PARITY_OUTPUT` for evidence; paired PNGs and `report.json` default to `apps/web/dist/parity-evidence/`.

The reference renders official components exported by the pinned submodule directly. The adapted side renders components registered by the actual plugins. Schedule registration uses unchanged official `mountAccess` with a controlled owner baseline, official ui-schedule apply, and the Workers Schedule RPC seam, asserting that page, sidebar, Session card and hover contributions all register. This fixture does not simulate production authentication: actual Connection/Gateway, generated `$mount`, authenticated Host snapshots and reconnect are verified by the session-adapter remote-access regression and full-shell acceptance. Controlled RPC fixtures cover empty, loading, error, list and manual-create states, plus the restored official Permission plugin and visible disabled Terminal/Session-log controls in en/zh. Permission selection exercises the official registered component and keyboard command path with a durable-receipt fixture; real policy enforcement and cross-tab projection updates are checked separately by Host and full-shell acceptance.

Each pair compares text, controls, disabled attributes, geometry and screenshot bytes at one viewport. Creation also checks draft retention after a Host refusal and identical retry arguments. Disabled Terminal/Session-log interactions cannot invoke actions.

**Scope:** this verifies selected components' visual/interaction contracts. It does not establish whole-application 100% parity or real Host support for all rules. Authentication, persistence, Session execution and the full shell need independent local/deployment acceptance. Browser time and timezone are fixed; focus is normalized before screenshots to remove background-tab focus differences.

Six feedback comparisons cover Session dialogs, message dialogs and like/dislike actions in both languages. All official surfaces stay visible and disabled without the conversation-log feedback service; interaction cannot submit. Shared labels use the official common dictionary.

Run `node apps/web/tests/parity/run-model-keyboard.mjs` for five cases: English/Chinese Enter/Tab paths keep unavailable models from submitting and retain the menu/explanation, while enabled models submit once; the shared directory also rejects missing and stale models. `run-commands.mjs` adds six cases for disabled `/model` popup options and keyboard paths.

`run-plugin-manager.mjs` covers four unchanged official unavailable-manager cases: visible disabled Add controls and a genuinely empty bundle catalog. Runtime inventory is independently shown by the official Settings built-in plugins page. `run-host-capabilities.mjs` adds six English/Chinese comparisons for the official directory browser's create refusal, retained draft, unchanged retry arguments and directory selection, plus precise fixed-agent View gating. A separate official built-in preset reference retains keyboard-accessible help; the product’s named default is Custom, not a fabricated Standard composition. These are not whole-application fidelity or persistent Host acceptance claims.

Account billing seam: `node apps/web/tests/parity/run-account.mjs` (four en/zh cases). Compare the original AccountSection under visible disabled billing semantics; pointer, keyboard, auxiliary-click and context-menu actions cannot navigate, while the unchanged AccountMenu retains identity and sign-out interaction. The fixture executes the actual seam registration and binds its declared locale to catch missing runtime translation.

Settings navigation integration: `node apps/web/tests/parity/run-settings-navigation.mjs`. Uses the real Cordis `SlotRegistry`, full official/adapted `apply`, and actual account/preset seams. Originals and shadows stay in raw inventory while navigation and onboarding project only winners; removing and restoring the account still yields one row. Four en/zh account/preset comparisons cover official SettingsRoot text, navigation, geometry and screenshot pixels, catching duplicate navigation that isolated component rendering cannot detect.

Sidebar branding is a registered user-approved deviation (2026-11-13): only the official `sidebar.brand.name` slot is occupied and the sidebar shows the code name `dsh-base` in every locale (the product display name `DeepSeek Harness Base` is used in README and documentation); the official mark fallback (`FishLogo` with click-to-copy version), layout, typography and interaction stay official. The one unavoidable difference is that the official name fallback's version line and click-to-copy version disappear with the slot. `run-sidebar-brand.mjs` and its fixture were deleted in Commit 1 and not restored, so the parity chain has no branding item.

File uploads: `node apps/web/tests/parity/run-upload.mjs`. English/Chinese official InputBar/ComposerAttachments reject image picker/drop intake locally under the Host's zero-image limit, making no upload request while ordinary file intake stays available. Original FileUploadRuntime uses a real Web Worker and Connection RPC over controlled HTTP to test receipts, failure details, cancellation and root-relative uploads from Chinese deep links. These six protocol cases do not replace real Host/R2 persistence and receipt-consumption tests.

`node apps/web/tests/parity/run-model-effort.mjs` adds four cases comparing supported root/effort menu pixels with the pinned official selector and exercises keyboard selection of off/low/high/max with exact requests, then checks the visible disabled effort entry, capability withdrawal, and model-only selection in English and Chinese. Shared directory refusal and `/model` field selection are covered by the fifth `run-model-keyboard.mjs` case; this is not a whole-application parity claim.

Separately, `pnpm acceptance:local` checks the built Worker, 108 inventory rows and enabled fibers, and public login without private RPC/WebSockets. `pnpm acceptance:browser-compat` runs seven cases for real PDF/Excel Workers and English/Chinese registration policies. Neither suite is counted in the 68 above. Deployment and provider calls still require independent remote acceptance.

Sidebar Session reference lifecycle: `node apps/web/tests/parity/run-sidebar-lifecycle.mjs`. Five cases use real official `ClientSessions`, `RemoteStream` and `SessionReference`: the original reports its own cancellation; the fork preserves actual rejection without that false diagnostic; switching retains the next view correctly; real Host failure remains an official error state; unexpected failure of an actively owned reference still reports. These are lifecycle contract cases, not pixel comparisons.

Remote semantic acceptance also requires one official turn per user request: tools and approval continuation occupy later steps of that same turn, pending approval cannot complete it, and a tool result precedes the end of its calling step. `acceptance-approval-ui.mjs` and `acceptance-official-ui.mjs` read real official `session/page` and verify one completion process per turn before and after reload, a completed success reason, and non-error tool results. Pro turns also require actual execution provenance of deepseek-official / provider-reported model, preserved after reload with Pro still visible in the model control. Approval sessionStats and the bilingual screenshot footer must match the actual journal turn/step counts. Run the assertion regression with `node apps/web/scripts/acceptance-turn-semantics.test.mjs`. This semantic requirement does not add to the offline browser case count above.

`node apps/web/tests/parity/run-chat-step.mjs` runs 4 bilingual cases using the actual official AssistantNodeView and TurnProcessNodeView: native per-Step journal versus shared SDK projection pixels/content, stable unique message IDs, no completion control while awaiting approval, one Turn with multiple Steps, replay and reload. This tests those actual renderers, not the complete Chat shell.

`node apps/web/tests/parity/run-composer-runtime.mjs` runs 4 actual official InputBar / SessionInputShell / Lexical / selector-bridge cases for rapid typing, paste and submission. The isolated fixture also passed under React 19; it does not substitute for the previously failing full desktop shell input scenario, which requires separate acceptance.
