# Browser comparison with official components

`run-anonymous-sidebar.mjs` compares the pinned official sidebar, top More menu and empty workspace browser with the marked forks in 12 en/zh, light/dark and expanded/collapsed/mobile-drawer cases. Sidebar and More use real SlotRegistry registrations; the workspace uses the official viewing store. Authenticated layout, icons, copy, styles, pixels and pointer actions must match. Captures clear focus and hover on both sides to avoid a transient Tooltip from drawer autofocus; no product region is masked and pixel matching is not relaxed. The actual anonymous composition is checked separately by `node apps/web/scripts/acceptance-anonymous-sidebar.mjs`: all eight locales in three sidebar modes, additional en/zh dark cases, clickable entries, public plugin/task browsing, pointer and shortcut authentication gates, both official top-menu items, bottom Settings/sign-in, the Hero workspace login gate, restored menu focus and nested-overlay Escape, complete public-page login return targets, and address preservation for 22 seconds after popstate inside the anonymous shell. Direct protected agent-document requests must still redirect to login; the return parameter contains the server-visible path and query, while the browser retains the fragment. Browser traffic must contain no private API requests, private WebSockets or 401s; separate direct unauthenticated requests must still return 401. The script uses the local build by default; an explicit `DSH_BASE_URL` selects Staging. It uses an isolated anonymous browser and does not read or write account preferences. Public anonymous browsing and authentication at the operation boundary are explicitly requested, tracked Host behavior differences; private RemoteAccess is unchanged.

`node apps/web/scripts/acceptance-auth-modal-local.mjs` uses temporary D1 and real Better Auth to verify the login dialog: desktop/mobile light and dark themes, official control dimensions, focus containment, close/backdrop/Escape, failed and successful username/email login, closed/open registration, safe returns and anonymous private API 401 responses. Accounts and writes exist only in the temporary local environment; this is not deployment verification.

`pnpm acceptance:auth-primitives` renders stable `Modal`, `Button` and `Input` exports from the pinned submodule as the reference for the local-account dialog's actual header, description, close control and form atoms. English/Chinese, light/dark and desktop/mobile cases compare geometry, computed styles, pixels and focused inputs. Consistent software rendering removes GPU raster noise without relaxing pixel thresholds. The runner is included in `acceptance:parity`. This verifies primitive reuse, not the existence of an identical official local-account flow.

Reference controls remain inside the same official Modal scrolling layer. Blank spacers and relative positioning only match the space occupied by the custom form; they do not copy or modify official styling. Focused comparisons activate each page immediately before reading or capturing it. Real login acceptance also covers a 390×360 short viewport: 24px vertical insets, internal scrolling, a reachable close control, and reachable Continue and Create account actions.

Run from the repository root:

```sh
pnpm acceptance:parity
```

The full command runs the remaining parity runners sequentially. `node apps/web/tests/parity/run.mjs` runs only the main reference cases; each runner retains its own report and scope, and the current complete command determines acceptance status. Not all cases are pixel comparisons.

The script uses the application's installed Vite and Puppeteer, builds an isolated fixture, starts a temporary local preview, runs Chromium, and closes both. It never accesses a deployed account, creates real tasks, or calls a model. All runners use the shared macOS/Linux/Windows browser finder. Set `CHROME_PATH` for the browser; paired PNGs and JSON reports default to `apps/web/dist/parity-evidence/`.

When running scripts that support directory overrides in parallel, give each script independent absolute `DSH_PARITY_BUILD_DIR` and `DSH_PARITY_OUTPUT` paths. Keep scripts without those overrides sequential; a preview must never read a directory another script is rebuilding. Isolate only artifacts and evidence, retaining every script's full scenarios and assertions.

The reference renders official components exported by the pinned submodule directly. The adapted side renders components registered by the actual plugins. Schedule registration uses unchanged official `mountAccess` with a controlled owner baseline, official ui-schedule apply on the reference side, the complete marked Schedule fork on the adapted side, and the Workers Schedule RPC seam, asserting that page, sidebar, Session card and hover contributions all register. This fixture does not simulate production authentication: actual Connection/Gateway, generated `$mount`, authenticated Host snapshots and reconnect are verified by the session-adapter remote-access regression and full-shell acceptance. Controlled RPC fixtures cover empty, loading, error, list and manual-create states, plus the restored official Permission plugin and visible disabled Terminal/Session-log controls in en/zh. Permission selection exercises the official registered component and keyboard command path with a durable-receipt fixture; real policy enforcement and cross-tab projection updates are checked separately by Host and full-shell acceptance.

Each pair compares text, controls, disabled attributes, geometry and screenshot bytes at one viewport. Every screenshot goes through `stability.mjs`: `settle()` waits for `document.getAnimations()` to finish, two `requestAnimationFrame` turns and one quiet frame before capturing; a pixel mismatch re-settles and retries up to three times, and only a final mismatch fails. Each retry prints `{"parityRetry":{label,attempts}}` so a case that always needs retries is visible. The criterion stays exact pixel equality; thresholds are not relaxed. Creation also checks draft retention after a Host refusal and identical retry arguments. Disabled Terminal/Session-log interactions cannot invoke actions.

**Scope:** this verifies selected components' visual/interaction contracts. It does not establish whole-application 100% parity or real Host support for all rules. Authentication, persistence, Session execution and the full shell need independent local/deployment acceptance. Browser time and timezone are fixed; focus is normalized before screenshots to remove background-tab focus differences.

Six feedback comparisons cover Session dialogs, message dialogs and like/dislike actions in both languages. All official surfaces stay visible and disabled without the conversation-log feedback service; interaction cannot submit. Shared labels use the official common dictionary.
